# SPEC — pyqt-omniviewer

> **Контекст: хакатон.** Это приложение разрабатывается в рамках хакатона. Победитель
> определяется по **числу типов файлов, которые приложение способно отобразить**.
> Поэтому приоритеты жёсткие:
>
> 1. **Скорость разработки важнее глубины.** Каждый отдельный просмотрщик делается
>    по принципу «минимально достаточно, чтобы показать содержимое». Никаких
>    редакторов, аннотаций, конвертеров, продвинутой навигации внутри формата.
> 2. **Ширина охвата важнее полировки.** Лучше 40 форматов «просто отображаются»,
>    чем 10 форматов с богатым UX.
> 3. **Всегда есть fallback.** Любой нераспознанный файл всё равно «отображается»
>    (текст → hex + метаданные), поэтому формально приложение показывает *всё*.
> 4. **Строгое ограничение задачи:** просмотр решается **только библиотеками,
>    линкуемыми в процесс**. Запрещены запуск внешних процессов/бинарников
>    (`soffice`, `pdftoppm`, `ffmpeg`-CLI, `unrar`, …) и любые сторонние GUI-приложения.

---

## Problem Statement

Пользователю нужно быстро посмотреть содержимое произвольного файла на диске, не
открывая для каждого типа своё приложение. Файлы бывают самые разные: тексты, код,
документы (doc/docx/odt/rtf), таблицы (xls/xlsx/csv), презентации, PDF и электронные
книги, изображения (включая HEIC/AVIF/RAW/SVG), аудио и видео, архивы, а также
множество мелких форматов (json/yaml/xml/ini, шрифты, письма, ipynb). Штатные
средства ОС либо требуют установки тяжёлых пакетов, либо запускают внешние
редакторы, либо просто не умеют часть форматов.

## Solution

Настольное приложение на Python + PyQt6 с двумя панелями:

- **Слева** — область просмотра содержимого выбранного файла.
- **Справа** — дерево файлов выбранной папки (расположение — по ТЗ; есть кнопка
  «поменять панели местами»).

Пользователь выбирает папку, кликает файл в дереве — слева сразу появляется
адекватное представление содержимого. Тип определяется по содержимому
(`QMimeDatabase`), под каждый тип подбирается свой лёгкий просмотрщик из реестра.
Для форматов без хорошего представления показываются извлечённый текст, hex-дамп
первых килобайт и таблица метаданных — так «отображается» любой файл.

Всё работает офлайн, без внешних приложений, ставится на чистую Ubuntu 24.04 из
`requirements.txt` + списка `apt`-пакетов.

## Implementation Decisions

### Технологический стек

- **Python** — целевая 3.12 (Ubuntu 24.04), `requires-python = ">=3.10"`.
- **GUI** — **PyQt6**. Плюс `PyQt6-WebEngine` для HTML/MHTML/сложный SVG/EPUB(альт.)/ipynb.
- **Лицензия проекта — AGPL-3.0** (вынужденно: PyMuPDF распространяется под AGPL).
- Никаких вызовов внешних процессов/приложений в коде продукта. Допускаются только
  библиотеки, работающие in-process (в т.ч. нативные: libmupdf, libarchive,
  Qt Multimedia FFmpeg-бэкенд как часть Qt).

### Определение типа файла

- `QMimeDatabase.mimeTypeForFile` с контентным сниффингом. `python-magic` не используется.
- Диспетчеризация просмотрщиков — по MIME-типу (с учётом наследования MIME), с
  запасным разбором по расширению.

### Архитектура просмотра

- **`ViewerRegistry`** — реестр обработчиков. Каждый обработчик наследует
  **`BaseViewer`** и объявляет поддерживаемые MIME-типы и приоритет. Реестр по файлу
  возвращает виджет просмотра. Обязателен зарегистрированный fallback-обработчик,
  подходящий под любой файл (низший приоритет).
- Интерфейс обработчика (форма, не финальный код):

  ```
  class BaseViewer(QWidget):
      mime_types: tuple[str, ...]        # какие MIME берёт
      extensions: tuple[str, ...]        # запасной матч по расширению
      priority: int = 0                  # выше — предпочтительнее при конфликте

      @classmethod
      def can_handle(cls, path, mime) -> bool
      def load(self, path) -> None       # синхронная лёгкая подготовка
      def load_async(self) -> None       # тяжёлый рендер в QThreadPool (опц.)
      def cancel(self) -> None           # отмена при смене выбора
  ```

- Тяжёлый рендер (страницы PDF, разбор больших таблиц, миниатюры) выполняется в
  `QThreadPool`/`QRunnable` с поддержкой отмены при смене выделения в дереве.
- Каждый вызов `load`/рендера обёрнут: исключение превращается в «ошибочный»
  виджет с сообщением и разворачиваемой трассировкой, приложение не падает.
- **Минимализм просмотрщиков** (требование хакатона): реализуется только отображение
  содержимого + для изображений/PDF — вписывание в окно, зум, панорамирование/прокрутка.
  Выделение текста в PDF, боковые панели миниатюр страниц, оглавление, поворот,
  редактирование, поиск внутри документа — вне scope MVP (могут быть добавлены
  позже как stretch, если останется время).

### Модули приложения

- Главное окно: `QSplitter` с областью просмотра и деревом; действие «swap panels»;
  тулбар навигации; строка статуса.
- Панель дерева: `QFileSystemModel` + `QTreeView` + `QSortFilterProxyModel`
  (фильтр по имени, «папки сверху»), адресная строка, кнопки навигации, история
  «назад/вперёд», `QFileSystemWatcher`.
- Панель метаданных: единый сборщик свойств поверх `hachoir` + `Pillow`/`piexif`
  (EXIF) + `mutagen` (аудиотеги) + PyMuPDF (свойства PDF) + `QFileInfo`.
- Модуль миниатюр (после MVP): фоновая очередь + дисковый кэш по
  freedesktop thumbnail spec (`~/.cache/thumbnails`).
- Состояние — `QSettings` (INI в `~/.config`): геометрия окна, последняя папка,
  поле/направление сортировки, «папки сверху», ориентация панелей, режим миниатюр,
  пороги больших файлов.

| Email | eml, msg | stdlib `email`; `.msg` — `extract-msg` |

### Обработка больших файлов

- Текст/hex: чтение окном (по умолчанию первые ~5 МБ, подгрузка при прокрутке).
- Изображения: если сторона > порога (по умолчанию ~8000 px) — уменьшение при загрузке.
- Пороги настраиваются в `QSettings`.

  набор `gstreamer1.0-plugins-*` + `gstreamer1.0-libav`).
- `qt6-image-formats-plugins` — дополнительные форматы изображений для Qt.
- `libarchive13` — для `libarchive-c`.
- Опционально: `libmpv2` — для запасного движка `python-mpv`.
- Doxygen: пакет `doxygen` (только для сборки документации, не для рантайма).
- Полный список — в `README` и `install.sh`.

## Testing Decisions

### Что считается хорошим тестом

- Проверяется **внешнее поведение**, а не детали реализации: «по этому файлу реестр
  выдаёт просмотрщик, и он загружает содержимое без исключения», а не «внутри
  вызвался такой-то метод».
- Тесты не зависят от наличия дисплея: GUI-часть гоняется под `xvfb`
  (`QT_QPA_PLATFORM=offscreen` где возможно).
- Тесты работают на фиксированном наборе `demo/`, а не на случайных файлах системы.

### Основной шов (seam)

- **`ViewerRegistry` — единственный и главный шов.** Вход: путь к файлу. Выход:
  экземпляр `BaseViewer`. Практически всё тестируется через него:
  1. `registry.viewer_for(path)` возвращает ожидаемый класс просмотрщика для
     каждого типа из `demo/` (таблица «файл → ожидаемый класс»).
  2. Для каждого файла из `demo/`: `viewer = registry.viewer_for(path); viewer.load(path)`
     и (если есть) синхронно дождаться `load_async` — не должно быть исключений,
     виджет создан, это не «ошибочный» виджет.
  3. Нераспознанный/битый файл → возвращается fallback-просмотрщик, он тоже
     загружается без исключения.
  4. Повреждённый файл каждого типа (обрезанный) → просмотрщик не падает, отдаёт
     «ошибочный» виджет с сообщением.

### Вспомогательные швы

- **Определение типа**: таблица «путь → ожидаемый MIME» на образцах `demo/`,
  включая файлы без расширения.
- **Сборщик метаданных**: по каждому образцу возвращает непустой набор базовых
  полей (размер, mime, даты); для изображения с EXIF — присутствуют поля камеры;
  для аудио с тегами — присутствуют artist/title.
- **Модель дерева/прокси**: сортировка по каждому полю даёт ожидаемый порядок на
  фиктивном наборе; «папки сверху» соблюдается; фильтр по подстроке отсекает
  лишнее.
- **Чтение больших файлов**: на сгенерированном большом текстовом файле в память
  читается не больше порога.

### Модули под тестами

- `registry` (основное), `mime`-определение, `metadata`, `filetree`-прокси-модель,
  утилита оконного чтения. Отдельные просмотрщики — только через `registry` в
  смоук-прогоне по `demo/`.

### Прио и объём

- Прогон в CI: `ruff` (линт) + `pytest` под `xvfb`. Цель смоука — «ни один тип из
  `demo/` не роняет приложение и открывается своим просмотрщиком».
- Прогон `doxygen Doxyfile` в CI (не должно быть фатальных ошибок).

### Прототипов в этом spec нет

Интерфейс `BaseViewer` выше — проектное решение, а не результат прототипа.

## Out of Scope

- Любое **редактирование** файлов; сохранение, конвертация между форматами,
  экспорт.
- Продвинутый UX внутри форматов: выделение/копирование текста из PDF, боковая
  панель миниатюр страниц PDF, оглавление/закладки, поворот изображений,
  слайд-шоу, покадровый разбор видео, редактор метаданных, поиск внутри документа.
  (Часть может быть добавлена как stretch после того, как охват форматов
  максимизирован.)
- Пиксельно-точный рендер офисных документов (doc/docx/odt/ppt/xls) — из-за
  запрета на внешние приложения показываем текст + структуру + вложенные
  изображения.
- Форматы, требующие внешних конвертеров без in-process библиотеки:
  DWG (проприетарный), полноценный STEP/IGES-рендер — только если найдётся
  библиотека и останется время (фичефлаг «3D/CAD»).
- Работа с сетевыми/облачными расположениями, FTP/SMB, архивами внутри архивов
  глубже разумного предела рекурсии.
- Установочные пакеты (`.deb`, AppImage, PyInstaller) — запуск из исходников по
  документации.
- Windows/macOS — целевая платформа Ubuntu 24.04.
- Многоязычная локализация интерфейса (UI — русский; отдельная задача при
  необходимости).
- Полноценная система плагинов с загрузкой сторонних `.py` в рантайме — реестр
  внутренний, расширяется правкой кода.

## Further Notes

- **Стратегия «победить по числу форматов».** Порядок работ: (1) каркас
  (окно, дерево, реестр, fallback) — уже даёт «отображается всё»; (2) Tier-1
  просмотрщики (текст/код, изображения, PDF+книги, таблицы, медиа, архивы, HTML,
  Markdown); (3) вширь — Tier-2 (office как текст, ipynb, шрифты, email, RAW,
  json/yaml-дерево); (4) остаток времени — stretch-фичи и Tier-3/CAD.
- Каждый новый просмотрщик — это один небольшой модуль + одна запись в реестре +
  один образец в `demo/` + одна строка в таблице тестов и в разделе README.
  Стоимость добавления формата должна оставаться низкой — это ключ к победе.
- Раздел README «Поддерживаемые форматы» ведём с первого коммита и обновляем
  вместе с каждым новым обработчиком; он же — материал для демо-видео и защиты
  перед жюри.
- Безопасность: имена файлов и записей архивов не подставляются ни в какие
  команды (внешних команд нет вообще); пути из архивов проверяются на выход за
  пределы временной папки (Zip Slip); рекурсия по вложенным архивам ограничена по
  глубине и суммарному размеру.
- `hachoir` даёт «дерево полей» почти для любого бинарного формата — это дешёвый
  способ формально расширить «поддержку» на десятки экзотических типов через один
  fallback-обработчик.
